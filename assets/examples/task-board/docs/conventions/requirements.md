# 需求编写规范

## 范围与归属

适用于任务板行为变化；具体主题存 docs/requirements/，本文件仅定义写法。复杂需求写背景/范围/规则/异常/AC；单模块变化简写目标、边界、AC；局部文案修正用一句话加可验证条件，沿用 Issue 或对话。关键含义先澄清，未知不阻碍的部分标待确认。

## 具体规则

写清本机用户场景、输入和可见结果；没有账户能力不能自行添加角色模型。成功/非法输入/不存在/重复操作按影响选 AC。AC 稳定编号，给前置、动作、结果；当前、计划、已实现、已验证分别写。新用户要求修订具体主题与旧/新 AC 关联，一般无需改本写法；旧要求仍有效时报告实现冲突。

## 正确例与反例

正确（具体主题 tasks.md）：AC-T3，已有未完成任务，POST complete 返回 done=1；再次调用返回相同任务。错误：“支持完成，功能正常”，无法检验重复行为。

## 检查

逐条将 AC 对应输入、输出与 tests/test_tasks.py 的测试或 UI 人工步骤；核对边界歧义、状态、修订依据。没有执行的浏览器步骤记录未验证，不能用构建替代。
