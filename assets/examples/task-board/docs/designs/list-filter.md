# 新增列表筛选方案

状态：已实现；基线自动检查与二选一页面验收已通过，其他 UI 项按实际范围记录。对应 [需求与 AC](../requirements/list-filter.md)。

1. **涉及模块**：既有 HTTP、service、storage、前端请求与页面、tests。跨接口和多模块，故保存独立短方案；没有新服务或固定层次要求。
2. **各处改动**：http.py 解析 include_done；service.py 接收布尔条件；storage.py 在默认查询加 done=0；api.mjs 序列化 0/1；index.html 增加关联标签的复选框；page.mjs 读取条件并刷新；tests/test_tasks.py 增加默认/全部/非法输入验收。沿目录规范现有位置，无新目录。
3. **数据流**：checkbox → page → api → GET query → http 校验 → service → storage → 按 id 排序的 JSON → DOM。完成后按当前条件重新加载，筛选不写入数据库。
4. **接口入出参**：GET /api/tasks?include_done=0|1，省略为 0；200 [{id,title,done}]，非法/空/重复 400 {error}；创建和完成接口不变。
5. **失败处理**：非法参数在查询前拒绝；查询未知异常不假成功；页面显示错误与重试，保留勾选状态；写入失败按原事务回滚。无外部重试任务。
6. **兼容影响**：原默认全部改为未完成，同仓客户端同时改；未知外部客户端待确认。schema、迁移和现有任务数据不变，迁移不适用。
7. **验证**：F1/F2/F3 映射两项新增 unittest；完成/创建/约束继续回归。JS 语法与 build 只证明相应静态范围；F2/F4/F5 页面、键盘/视口按 UI 规范独立记录。
8. **恢复**：停止本地服务，回退筛选这批应用/测试/需求/方案改动后重启；保留 tasks.sqlite3，不把应用回退称数据恢复。此前全列表代码可从示例历史取得；生产部署/数据恢复不在本例。

通用目录、语言、前端和写法约定未变；具体功能规则保存在需求/方案，未创建账本或新迁移。
