# 前端工程规范

> 按实际框架、目录与构建配置填充并删除提示。工程组织在本文件，交互与视觉在 UI 规范。

## 范围

- 框架/构建工具/版本证据：（清单、锁文件、配置）
- 页面、组件、路由、状态、网络层路径：（与入口目录树一致）

## 可执行规则

- 页面负责路由/数据协调，公共组件接收明确参数与事件；业务逻辑位于（实际位置），公共组件不得导入业务页面。
- 路由与权限在（约定入口）维护；服务端仍验证权限，前端隐藏按钮不能代替权限控制。
- 服务端数据由（请求层/缓存）维护，页面瞬时状态留在页面，共享状态按（实际约定）；禁止复制同一事实到多个 store。
- 所有请求经过（API 适配路径）；统一处理鉴权、错误协议、超时/取消及过期响应。URL/环境配置位于（真实配置），禁止散落页面。
- 表单提交防重复；加载、失败、空、无权限与重试遵循 UI 规范。
- 新组件优先查（公共组件位置），只有稳定复用需求才提取；构建产物由工具生成，不手改。

## 小例与检查

教学例（假设入口采用 pages/components/api 分层，生成时替换为项目事实）：

`pages/OrderPage → api/orders.cancelOrder`：页面维护 pending/error，API 层映射协议错误；请求完成后按返回结果更新页面。`components/ConfirmDialog` 只接收文案、pending 与确认/关闭事件，不导入 OrderPage 或调用订单接口。

检查失败响应后 pending 是否复位、错误是否可见，连续操作的过期响应是否覆盖新结果。

| 触发 | 检查与工作目录 | 来源/状态 |
|---|---|---|
| 前端代码变化 | （lint/typecheck/test/build 真实命令） | （配置/实际结果） |
| 请求/共享状态变化 | （过期响应、错误、权限和回归检查） | （结果或未验证原因） |

## 检查证据的边界

为上面的每条规则选择实际适用的验证，并注明结果；不存在的工具写未配置。

| 类型 | 填写内容 | 能证明的范围 |
|---|---|---|
| 编译/lint/文本线索 | 真实命令、配置、定位结果 | 语法/静态约束或候选；文本命中不是行为证明 |
| 语义审查 | 受影响代码、调用方、规则/AC 对照 | 本次已阅读范围与判断；列未读边界 |
| 行为测试 | 输入/状态、预期结果、真实测试路径/命令 | 实际执行场景；不外推所有异常或环境 |
| 人工 UI 检查 | 页面状态、视口、键盘/焦点步骤 | 实際操作范围；无 UI 写不适用依据 |
