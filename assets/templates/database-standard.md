# 数据库规范

> 按实际数据库、schema/迁移工具与数据访问代码填写；无持久化不生成。当前模型文档和一次迁移方案另存。

## 范围与来源

- 数据库类型/版本依据、schema、迁移、访问层位置：（真实路径/配置）

## 可执行规则

- 表/列/主键/外键命名遵循（现有约定）；唯一性、非空与关系约束写进 schema，不能只依赖页面校验。
- 每个新字段说明含义、单位、时区/精度、空值与默认值；敏感数据限定读写角色与日志边界。
- 参数化查询；排序/列名等动态结构使用白名单；业务模块不得绕过（访问层）散落 SQL。
- 索引由真实查询模式支持，说明读写代价，并用（实际 explain/查询验证方式）核实；不以“可能有用”堆索引。
- 一个业务原子操作在（事务位置）提交；并发更新采用（真实锁/版本/约束）保证不变量，外部副作用和失败恢复明确分开。
- 迁移文件放（目录），已执行迁移不重写；变更评估旧数据、旧/新应用兼容、回填、锁与恢复。破坏性变更先列影响与批准条件。

## 小例与验证

教学例：业务要求“一个用户只能有一个同名收藏夹”时，以 `(user_id, name)` 的数据库唯一约束兜底，并验证并发创建只产生一条记录；API 层将冲突映射为明确业务错误。仅先查再写不能保证并发唯一性。

生成时写出实际 schema/迁移与测试路径、数据库方言和冲突映射；查询参数使用真实驱动的绑定 API，不把用户字符串拼进 SQL。

| 变更 | 检查/真实命令 | 结果/限制 |
|---|---|---|
| schema/查询/事务 | （迁移验证、约束/回滚/并发测试、查询计划） | （运行环境、未验证部分） |

## 检查证据的边界

为上面的每条规则选择实际适用的验证，并注明结果；不存在的工具写未配置。

| 类型 | 填写内容 | 能证明的范围 |
|---|---|---|
| 编译/lint/文本线索 | 真实命令、配置、定位结果 | 语法/静态约束或候选；文本命中不是行为证明 |
| 语义审查 | 受影响代码、调用方、规则/AC 对照 | 本次已阅读范围与判断；列未读边界 |
| 行为测试 | 输入/状态、预期结果、真实测试路径/命令 | 实际执行场景；不外推所有异常或环境 |
| 人工 UI 检查 | 页面状态、视口、键盘/焦点步骤 | 实際操作范围；无 UI 写不适用依据 |
