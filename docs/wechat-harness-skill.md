# 让 AI 按项目规矩写代码：从“新增列表筛选”走一遍

让 AI 写一个列表筛选，代码往往很快就有了。更难判断的是：筛选条件在哪一层校验？请求失败后页面保留什么？默认行为变化会影响哪些调用方？下一次需求改了，旧文档还能不能继续指导开发？

`ai-project-conventions` 把这些答案留在项目中。它先读真实代码、配置、测试、CI 和已有文档，再填写一个项目入口与几份适用规范。人能打开文件审阅，AI 能在开工时按任务读取。项目变了，再同步实际受影响的内容。

## 项目会得到哪些文件

新项目可以采用下面的目录。已有项目沿用现有路径，不为了统一名字搬动文档。

```text
AGENTS.md                              # 或实际工具使用的 CLAUDE.md
docs/
  conventions/
    directory-structure.md             # 文件归属、依赖方向
    python-standards.md                # 本项目实际语言规则
    javascript-standards.md            # 有对应语言才生成
    frontend-standards.md              # 前端组织与请求/状态边界
    ui-standards.md                    # 视觉、交互与验收
    database-standards.md              # 模型、约束、索引、事务、迁移
    requirement-standards.md           # 需求怎样写
    technical-design-standards.md      # 方案怎样写
    testing-standards.md               # 测试怎样选、放、运行
  requirements/list-filter.md          # 这个功能的具体需求
  designs/list-filter.md               # 这个功能的具体方案
```

这是教学项目的适用集合。Go 或 Java 项目填写自己的语言规范，无前端或数据库就不建对应空文件；没有具体功能任务，也不生成虚构需求与方案。

最后两份文件与写法规范有不同用途。`requirement-standards.md` 教怎样描述规则和验收，`requirements/list-filter.md` 填这次功能的答案。方案也是如此。一项筛选条件变化通常修订具体需求、方案和测试；写法本身改变才修改规范。

## 入口让 AI 知道去哪里写

入口包含项目定位、模块或服务全景、架构铁律、真实技术栈、目录摘要、运行/测试/构建命令，以及“什么任务必须先读什么”。

教学任务板只有一个本地服务，使用 Python 标准库、SQLite 和原生 JavaScript。浏览器请求依次经过 HTTP、业务服务、数据访问：

```text
app/server.py    组装依赖，管理连接与服务生命周期
app/http.py      解析请求，映射响应和错误
app/service.py   校验业务输入，调用 repository
app/storage.py   参数化 SQL、事务和行映射
web/api.mjs      统一请求和协议转换
web/page.mjs     页面状态、事件与 DOM
```

详细归属由 `directory-structure.md` 权威维护：测试放 `tests/test_*.py`，迁移放 `migrations/NNN_*.sql`，配置、脚本、需求、方案与生成物分别有位置。HTTP 不写 SQL，业务服务不导入 HTTP/SQLite，页面通过 API 模块发请求。目录规范同时给正确例、错误例和实际检查方式，入口保留概要即可。

技术栈和命令需要证据。`pyproject.toml` 声明 Python ≥3.11，CI 声明 3.11，本轮自动检查实际运行 3.14.7；这些是三种不同信息。项目没有 npm 清单或 lint 配置，就不能凭习惯写一个理想命令。

复杂多服务项目才增加局部入口，补本服务命令、数据层、外部依赖、定时任务与特有约定；简单项目用根入口说明。多个工具接入同一项目时，其他入口引用权威正文并补必要适配，避免复制后各自漂移。

## 先读规范，再写筛选验收

这次任务是：“新增列表筛选，默认只看待完成，勾选后看全部。”

AI 先读入口，再按其中路由必须先读前端、UI、需求与测试规范；影响到接口和查询，再读目录、语言、数据库与方案规范。前端规范指导请求、页面和状态的组织；UI 规范指导控件、真实 token、加载/空/错误状态、键盘与视觉验收，两者各管一类问题。

业务选择必须明确。这里的默认未完成属于教学需求；换成真实业务，如果默认条件尚未决定，就先澄清，不能拿示例替用户决定。

需求写成可观察的验收：

| 场景 | 验收结果 |
|---|---|
| 已完成与未完成各一项，默认加载 | 只显示未完成，按 id 升序 |
| 勾选“显示已完成任务” | 显示全部；取消勾选恢复未完成 |
| 参数为空、非法或重复 | 返回明确错误，数据不变 |
| 完成当前未完成任务 | 默认列表刷新后隐藏，全部列表可见 |
| 空结果或读取失败 | 有空/错误反馈；失败保留条件并能重试 |

需求粒度按实际影响选择：大需求写完整需求与方案，中需求写简化目标、规则和验收，可逆小改一句话加验收。这个功能跨页面、公共列表接口与查询，所以保存一份独立短方案。

方案回答八个问题：涉及哪些模块、各处改什么、数据怎样流动、接口入出参、失败怎样处理、兼容影响、怎样验证、出问题怎样恢复。它不要求所有项目采用同一种框架分层。

本例在原目录中实现 `include_done=0|1`：HTTP 解析参数，service 传条件，storage 绑定查询参数；API 序列化，页面管理勾选状态，HTML 使用有标签的原生复选框。schema 不变，无需凭空新增迁移或索引。

## 验证需要分清证据

规则检查分成四类：

- 编译、lint 或文本线索：检查语法、静态约束，或定位候选。
- 语义审查：阅读实际代码、调用方和规则，判断职责与契约。
- 行为测试：给定输入与状态，观察真实结果及失败后的数据。
- 人工 UI 检查：操作页面、视口、键盘、焦点与状态恢复。

搜索到 `catch` 不能证明所有异常处理正确；构建通过不能证明筛选交互正常；一组行为测试也不能证明所有环境都已验证。

本轮基线 11 项 unittest、两个 JS 模块语法检查和编译/静态复制通过。补充验证还用行为回归确认服务异常退出会关闭 SQLite 连接。真实浏览器验证了创建、完成后默认隐藏、勾选显示全部。执行状态记录在具体需求和验证记录中，计划、已实现、已验证分开。

## 条件后来变了，怎样同步

随后模拟新要求：“改成待完成、全部、已完成三种条件，默认仍待完成；旧客户端继续有效。”

`sync` 阅读新要求、差异、调用方与测试。接口增加 `status=active|all|done`，继续接受原 `include_done`，非法、重复或混用条件返回 400。页面改为有标签的原生 select。

这次实际更新 7 个代码/测试文件，以及具体筛选需求与方案。需求保留旧验收与新版本的关联，新增仅已完成、旧参数兼容和拒绝边界；方案更新八问及恢复步骤，测试验证真实结果。扩展后 13 项测试、JS 语法和 build 通过。

根入口和 9 份通用规范的哈希保持一致：目录、职责、技术栈、命令、schema 和写法没有变。具体条件放在功能需求里，不把每次产品调整写成通用工程规则。

真实浏览器也检查了三种条件、完成后刷新、停止服务时保留输入与条件、恢复按钮、重启后重试；390 与 1280 视口及键盘提交做了基础检查。读屏、量化对比度、GitHub CI/Python 3.11、未知外部客户端和生产环境仍未验证。

如果下一次变化增加独立查询模块，就要同步目录归属、入口概要与相关方案；如果修改通用测试命令，就更新测试规范和入口。同步范围由实际影响决定，必要历史继续保留。

## 怎样开始

在支持命名调用的代理中，可以表达：

```text
$ai-project-conventions init
$ai-project-conventions check
$ai-project-conventions sync origin/main
$ai-project-conventions audit origin/main
$ai-project-conventions add standard directory
```

这些是代理操作语义，本包没有同名终端 CLI。`init` 填写适用文件，`check` 对照规则并运行真实检查，`sync` 更新实际影响，`audit` 只读找漂移，`add` 补一种明确需要的产物。`workflow/resume` 保留为可选辅助，日常开发无需强制阶段或账本。

技能核心独立于特定代理 API 和个人绝对路径。跨工具发现与加载需要在真实客户端验证，复制文件不等于加载成功。当前文件契约版本 3.2.0，六类 32 个稳定规则 ID 与正文保留；更新个人技能也不会自动升级业务项目。

[GitHub 分支](https://github.com/owl-go/ai-convertion/tree/codex/engineering-harness) 保存完整模板、填实项目和可重放同步补丁；[验证记录](conventions-validation.md) 列出实际检查与未验证范围。文章为交付稿，尚未发布。
