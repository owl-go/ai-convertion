# 跨工具核心与入口适配

核心为 `SKILL.md`、`references/`、`assets/templates/`；`scripts/` 是可选 Python 3 只读辅助，不要求特定代理、MCP、云服务或固定运行时。`agents/openai.yaml` 只提供本机 Codex UI 元数据，核心流程不依赖它。

## 使用与复制

将完整技能目录复制到目标工具实际支持的技能目录即可携带入口、核心、模板和辅助脚本；技能 ID 为 `ai-project-conventions`。目标工具的发现、参数传递和重新加载方式以其现有配置或已核实文档为准。若只需要核心规范，可复制 `references/` 与 `assets/templates/`，在目标项目入口加按变更条件读取的路由；不声称复制本身完成了工具加载。

安装包内部链接使用相对路径，项目生成文档则路由到项目内采用的快照。无需依赖源机器的绝对路径。用户可在支持命名调用的工具中传达 `ai-project-conventions init /project/path` 等意图；`$ai-project-conventions` 是本机 Codex 调用示例，其他工具语法需要其实际依据。

## 按证据适配项目入口

先检查项目既有代理入口、工具配置与适用作用域，沿用已生效的文件和合并规则。新项目工具未知时创建供应商无关的项目规范索引并标记入口接入待确认；有证据后生成相应入口。所有入口只保留短路由、必要红线与真实命令，共同指向同一项目权威规则，不复制完整六类正文。

已有 `AGENTS.md`/`CLAUDE.md` 镜像约定或显式 `add agents` 时，以 `AGENTS.md` 为编辑源，将合并后的有效人工内容写入二者，用 `cmp -s AGENTS.md CLAUDE.md` 验证。仅一个入口或各入口有独立作用域时保持项目约定，不能把另一工具的内容强制覆盖。为统一规则，可共用 [工具中立入口模板](../assets/templates/project-instructions.md)；兼容双入口用 [AGENTS 模板](../assets/templates/AGENTS.md)。

入口路由覆盖：模块边界→架构；代码行为/资源/依赖→代码；数据结构/迁移→数据库；业务行为/验收→需求；验证/回归→测试与门禁；页面/交互→UI；长期任务/交接→账本。只写真实存在、在相应作用域可访问的路径。

## 验证边界

包级检查验证 frontmatter、相对链接、模板与规则覆盖；辅助脚本检查证明其实际运行范围。工具适配验证需真实加载配置和一次可观察读取；只有完成才称该工具已验证。未安装/未运行的客户端明确列为未验证，既有入口文件名并不能证明客户端读取成功。复制核心包、初始化项目和发布外部平台是不同操作，依用户要求选择范围。
