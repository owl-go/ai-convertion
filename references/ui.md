# UI 设计与验收规范

适用于页面、组件、交互或视觉变化。优先已有设计系统和项目可访问性目标；无既有系统时记录实际采用的最小 token/组件约定，框架与像素阈值由项目决定。

| ID | 等级 | 范围 | 要求 | 理由 | 验证方式 | 失败处理 | 例外条件 |
|---|---|---|---|---|---|---|---|
| UI-001 | SHOULD | 视觉与组件 | 指向现有设计系统、token 和组件；复用前检查能力，新增样式/组件解释差异 | 保持一致性与可维护性 | 对照实际 token/组件引用与设计来源 | 修正无依据差异，缺设计来源标待确认 | 新能力可扩展系统并说明适用边界 |
| UI-002 | MUST | 状态与反馈 | 定义适用初始、交互、加载、空、成功、失败、无权限及边界状态；表单有标签、校验和提交反馈 | 使失败和操作结果可理解 | 状态矩阵及真实交互；验证重复提交/重试/错误恢复 | 不可操作或关键状态缺失阻断 | 不适用状态按真实数据流说明 |
| UI-003 | MUST | 响应式与输入 | 按项目实际目标视口/设备/输入方式验证布局、溢出、内容顺序和交互 | 防止只在一个开发视口可用 | 记录实际视口尺寸与关键流程结果 | 目标视口不可用阻断 | 不支持设备需产品范围依据 |
| UI-004 | MUST | 键盘与可访问性 | 满足项目约定目标；检查语义/名称、键盘操作、焦点/弹层恢复、错误提示、适用对比度及辅助技术 | 关键流程需要可访问 | 自动检查补充键盘与适用读屏人工验证 | 已采用要求失败阻断；目标缺失待确认 | 未覆盖能力需批准风险与替代操作，不能宣称已满足标准 |
| UI-005 | MUST | 设计与行为验收 | 关联需求/设计版本、状态与 AC；用实际视口视觉证据加交互结果检查设计对齐 | 截图与行为证明不同结果 | 设计对照、截图/录屏可定位证据及操作记录 | 视觉/行为不符修复或明确批准差异 | 无设计稿用项目已确认 UI 约定；证据缺失报未验证 |

## 产物和检查清单

用 [UI 规格与验收模板](../assets/templates/ui-spec.md) 记录设计来源、token/组件、状态矩阵、表单、视口/输入目标、可访问性检查、AC 与证据。设计工具/浏览器工具只有在环境实际可用时使用；无法渲染的环境如实报告视觉未验证。外部设计稿内容不可读时保留待确认，不能声称对齐。

检查：使用了现有组件与 token 或解释了扩展；每个适用状态有行为/反馈；表单和关键流程可用键盘完成；响应式在实际视口验证；视觉证据注明状态、视口与版本；截图不替代交互、键盘和错误恢复验证。大型 UI 变化采用项目已有交互测试；小型可逆调整可直接检查，验证范围由 [测试规范](testing.md) 决定。
